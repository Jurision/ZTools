# 鼠标复制粘贴与 ZTools 语音搜索辅助程序

这是已在 Windows 上实际使用并于 2026-11-12 验收的独立辅助程序源码。它不是 ZTools 插件，单独编译为 `SmartCopyPaste.exe`，不需要修改 ZTools 主程序。语音识别由微信输入法完成。

## 按键分配

| 操作                | 效果                                                         | 鼠标驱动里的设置                         |
| ------------------- | ------------------------------------------------------------ | ---------------------------------------- |
| 短按前进侧键        | 松开后复制 Ctrl+C                                            | Ctrl+Shift+F10，需按住时保持、松开时释放 |
| 长按前进侧键 ≥300ms | 松开后粘贴 Ctrl+V                                            | 同上，不能设置为循环宏或固定时长宏       |
| 短按中键 <350ms     | 打开 ZTools 并开始语音；录音期间再短按结束，保留搜索框和文字 | **标准鼠标中键**                         |
| 长按中键 ≥350ms     | 恢复原生中键按下，可继续按住拖动，松开释放                   | 同上                                     |
| 后退侧键            | 微信输入法原生开始／结束语音                                 | 左 Ctrl+左 Win+A                         |

ZTools 的唤起快捷键需为 `Ctrl+Space`，微信输入法的语音快捷键需为 `左 Ctrl+左 Win+A`。这些快捷键和时长目前在源码中固定，没有配置界面。复制／粘贴按时长明确分配，不猜测是否选中文字。

**不要把中键映射为 Ctrl+Space 或 Ctrl+Shift+F11。** 前者再次按下会收起搜索框；后者是遗留兼容入口，曾干扰输入法直接提交，产生“已复制，粘贴即可使用”。原生中键通过内部消息通知辅助程序，不经过这组额外快捷键。`Ctrl+Shift+F11` 目前仍会注册，需避免其他软件占用。

带 Ctrl、Shift、Alt、Win 的中键正常透传。左右键、滚轮、侧键和鼠标移动不被此中键监听拦截。无修饰键的普通中键短按已分配给语音，原生中键功能需要长按。

## 构建与隔离测试

要求 Windows x64 和 .NET Framework 4.x 编译器（通常随 Windows 提供），不需要下载 NuGet 包或安装新的运行时。在仓库根目录运行：

```powershell
pwsh -NoProfile -File tools/windows-input-helper/build.ps1 -Test
```

也可用 Windows PowerShell 的 `powershell -NoProfile -ExecutionPolicy Bypass -File ...`；此参数仅允许这次进程运行脚本，不更改系统执行策略。默认产物为本目录 `out/SmartCopyPaste.exe`；`-OutputDirectory` 可指定其他输出目录，支持空格。脚本只编译和自测，**不会安装、启动常驻程序、修改自启或替换正在使用的版本**。

自测采用单独的 `SelfTest.cs` 入口，运行 115 个断言（复制粘贴 14、语音 45、中键 56），结果写入新建的临时目录。覆盖短长按边界、重复触发、焦点变化、修饰键释放、超时、窗口身份、语音结束、原生中键释放、其他鼠标事件透传和有限重排时序。不会创建应用窗口、注册热键／鼠标钩子、模拟输入或读写真实 `.ztools`、剪贴板正文及已安装辅助程序的目录。

`SmartCopyPaste.exe --selftest` 是旧的本机诊断入口，会把报告写入 `%LOCALAPPDATA%\ZToolsSmartCopyPaste`；仓库验证请使用上面的 `build.ps1 -Test`，不要调用旧入口。

## 源码结构

| 文件                   | 职责                                                        |
| ---------------------- | ----------------------------------------------------------- |
| `HoldCopyPaste.cs`     | 消息窗口、热键、300ms 复制粘贴状态机、单实例入口及自测汇总  |
| `VoiceSearch.cs`       | ZTools 焦点确认、语音窗口识别、开始／结束状态机和组合键发送 |
| `MiddleButtonInput.cs` | 独立线程的中键监听、350ms 长按原生中键、有限监听重排        |
| `SelfTest.cs`          | 不启动常驻逻辑的隔离测试入口                                |
| `build.ps1`            | Windows x64 编译及可选隔离自测                              |

三个运行源码来自已验收的本机版本。本次归档补充方法注释、纠正过时注释，并把测试汇总抽为返回字符串，供隔离入口调用；运行时按键和状态机逻辑保持一致。没有收录早期“自动判断选区”的废弃脚本、安装包、运行日志、个人备份或鼠标驱动配置。

## 运行、停止与回退

构建不等于安装。需要部署时，先停止当前 `SmartCopyPaste.exe`，备份旧的可执行文件，再将构建产物复制至选定目录并启动。停止时可在任务管理器“详细信息”中结束 `SmartCopyPaste.exe`；中键会恢复系统原生行为。回退时停止新版，换回备份再启动。不要同时运行多个不同名称的副本。

当前程序使用命名互斥量 `Local\ZToolsSmartCopyPaste` 防止普通重复启动。它无托盘／设置窗口；状态日志位于 `%LOCALAPPDATA%\ZToolsSmartCopyPaste\status.log`，约 64KiB 后截断重写。日志包含时间、应用进程名、按住时长、错误和剪贴板变更序号，不保存复制内容或语音文字。

源码不自动添加开机自启，也不修改鼠标驱动、微信输入法或 ZTools 设置。如果从 MSIX 应用内安装，AppData／注册表可能被虚拟化，部署后必须从普通 Windows 进程核实实际位置和自启；不能以容器内读回值作为成功依据。

## 兼容性和验证边界

- 实际验收环境：微信输入法 3.0.2.36；语音面板通过进程 `wetype_update`、固定标题“语音输入”和窗口类 `wetype.flutter.setting` 共同识别。输入法版本更改这些身份后需要重新适配。
- ZTools 搜索框识别依赖进程名和标题 `ZTools`、窗口类前缀 `Chrome_WidgetWin_`；打开后等待焦点稳定约 300ms 再开始语音，切到其他应用则取消待执行动作。
- 输入法开始录音时也会安装鼠标监听，因此辅助程序在识别到语音面板后刷新中键监听，再于 350ms 后补一次；稳定录音中不持续重装。监听回调不做磁盘操作、进程查询、等待或键盘注入。
- 复制粘贴跳过 cmd、PowerShell 和名称含 terminal 的进程；普通权限程序无法保证给更高权限窗口注入按键。中键监听初始化失败时会记日志，原有复制粘贴仍可用。
- 辅助程序本身不读取或改写剪贴板正文，不清空／恢复剪贴板以掩盖问题。实际复制操作由目标应用的 Ctrl+C 完成；语音是否使用剪贴板仍取决于输入法和目标窗口。
- 真实用户验收已确认短按语音及长按中键正常；一次开始／结束语音观察中，ZTools 保持前台、文字保留，剪贴板变更序号不变。115 项自测不能代替未来输入法升级后的实际兼容性验证。

详细排查过程见 [微信语音兼容性记录](../../docs/voice-input-compatibility.md)。
