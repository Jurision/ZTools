# 硬盘文件搜索

主搜索框默认展示应用和运算结果，文件结果收起在底部的无文字细箭头中。普通文字停顿 250 ms 后查询本机文件，展开后显示最多 6 条；清空、更换查询或重新唤起时收起，空输入、计算结果、插件和粘贴附件场景不显示。中文至少一个字、其他文字至少两个字符才查询。文件预览固定按匹配度、全部类型和模糊模式查询，不继承专页的筛选；排除目录仍生效。设置中可关闭预览。

默认快速连按三下空格或点击预览底部箭头进入文件专页，也可自定义快捷键。粘贴路径只保留原文，文件结果同样先折叠。**文件专页是独立界面模式，不生成 `f` 或额外引号。** 查询只使用本机 Everything 索引，不读文件正文，也不把文件名或关键词发送到网上。

## 使用方法

以下查询示例在文件专页中直接输入，无需任何前缀。

| 输入或操作                          | 效果                                                        |
| ----------------------------------- | ----------------------------------------------------------- |
| 主框输入 `家人`                     | 显示软件和细折叠条，点击后展开最多 6 条文件结果             |
| 使用文件搜索快捷键                  | 进入文件专页，文字保持 `家人`，最多显示 200 条              |
| 专页输入 `家人 照片`                | 文件名同时匹配两个词                                        |
| `zyx`、`zhuyuanxin`                 | 模糊模式下匹配「朱元欣」等中文名                            |
| `家人\ jpg`                         | 限定路径包含 `家人\`，名字包含 `jpg`                        |
| `"D:\Program Files\Aurora\" aurora` | 引号中的路径作为完整片段，另匹配 aurora                     |
| `D:\APP\Aurora\Aurora mods.txt`     | 路径片段与文件名组合匹配，包括任意层级子目录中的 `mods.txt` |
| `"Annual Report"`                   | 引号中的空格保留，不拆成两个词                              |
| `re:^朱元[昊欣].*\.docx$`           | 正则搜索；格式错误或超过 256 字符时提示错误                 |
| 空框粘贴 `D:\Family Photos\a.jpg`   | 保留原路径；主框文件预览默认折叠，目标存在时排第一          |
| 主框连续三次空格                    | 用当前文字进入专页，不发出本次双空格翻译                    |
| 回车 / 点击                         | 打开选中的文件或文件夹                                      |
| Ctrl+回车 / Ctrl+点击               | 打开所在文件夹并选中该项                                    |
| Ctrl+Shift+C                        | 复制结果的完整路径，并提示已复制                            |
| 「返回搜索」                        | 返回综合搜索，保留当前查询文字                              |
| Esc                                 | 先清空查询，再退出文件模式，之后才隐藏窗口                  |

上下方向键或 Tab 切换选中项。专页内空格只用于分词，双击空格和 Ctrl+Shift+T 不触发翻译。输入框复制与结果的“复制路径”是两个独立操作。

未加引号的「路径 + 空格 + 文件名」会分词组合查询，不限一级子目录。手动输入和粘贴行为一致；如果整段恰好是真实存在的完整路径（路径或文件名可含空格），该目标优先排在第一。需要把含空格的路径片段作为整体约束时，可主动使用引号，例如 `"D:\Program Files\Aurora\" mods.txt`。这些搜索使用已有索引，不递归扫描实体硬盘。

直接粘贴单一路径时，是否按一个完整路径解析由内部状态记录，输入框原文不变；原本带引号的路径保留原引号。粘贴路径加关键词的查询也不会被再次整体包装。输入框有局部选区时只替换该选区，有文字且没有选区时按光标位置插入。主框单行文字直接进入输入框，多行文本保留文字块；两者都不自动翻译。文件专页内粘贴普通文字作为查询。

兼容旧的 `f 关键词` 入口：在主框手动输入或整体粘贴旧命令时，只将它转换为文件搜索模式并移除入口标记，不再生成第二个 `f`。进入专页后继续输入文字不会自动添加前缀。

主框双击空格后等待 401 ms；400 ms 内再按第三次则进入文件专页，取消待发翻译。其他按键、输入法组字、切换页面或新搜索会话取消待发手势。

专页的「模糊 / 精确」、排序和升降序会记住；主框的折叠文件预览固定为全部类型、模糊匹配和相关度排序。类型在本次搜索中保留，每次重新唤出搜索窗口恢复「全部类型」。有类型筛选且没有结果时，提示当前筛选，并提供清除入口。

## 匹配和排序

- 不区分英文大小写；全角、半角输入会归一化。多个词按“同时满足”匹配，普通词只匹配文件名；带路径分隔符或盘符的词匹配完整路径。
- 「精确」指原字包含匹配，并非要求整个文件名完全相同；不做拼音、插字、错字匹配。
- 「模糊」依次优先显示：名称相同、开头相同、包含原字、拼音、中间多出少量字、少量错字。例如「家人」可以带出「家里人」，「朱元昊」可以带出「朱元欣」，原字结果始终在前。
- 专页提供相关度、名称、修改时间、大小、类型五种排序；后四种可切换升降序。无论次级排序如何，始终先放原字匹配，再放拼音、插字和错字匹配；类型排序在每组内始终让文件夹靠前，再按类别排列。
- 相关度内部先按匹配档位排列。只有同一档内，才用本机成功打开的次数、最近打开时间提升常用项；历史不能让模糊结果超过原字结果，也不会让仅包含匹配越过名称相同的结果。名称、时间、大小、类型排序不使用历史加权。
- 文件专页至少输入 1 个中文字符或 2 个其他字符才查询。输入或筛选改变后立即撤下旧行，停顿约 150 ms 再查询，先返回原字结果，再合并模糊结果；旧响应不会覆盖新结果。

## 设置与排除目录

应用结果、折叠文件预览和文件专页的右键菜单均提供「从搜索结果中隐藏」。应用按启动目标和入口隐藏（包含同一目标的别名）；文件/文件夹按完整路径精确隐藏，不会删除文件，不排除其他位置同名文件，也不递归排除文件夹子项。隐藏规则保存在本机，重新打开后仍生效；直接输入已隐藏文件的完整路径也不会恢复它。

恢复：设置 → 常规 → 默认搜索范围，找到「右键隐藏的应用入口」或「右键隐藏的文件或文件夹」，删除对应行并保存。应用有快捷方式和目标程序两行时，两行一起删除。旧的按名称隐藏和目录片段排除仍独立保留。

在设置的「搜索范围」中找到「硬盘文件搜索」：

- 「主搜索框显示折叠文件预览」默认开启；关闭后主框不查询文件，仍可通过快捷键进入专页。翻译和文件触发方式在常规设置的“搜索动作快捷键”中分别配置。
- 「不搜索这些文件夹」每行填一个 Windows 路径片段，不区分大小写。例如 `D:\临时文件\`。清空列表表示不排除目录；此设置只影响结果，不删除任何文件。
- 默认排除 Windows、ProgramData、回收站、恢复目录、WindowsApps、AppData，以及 node_modules、.git、Python 和常见应用缓存目录。普通 Program Files 不被整体排除。

功能是主程序内置的，不需要打开插件搜索。文件有轻量折叠预览和独立专页，主框预览不包含专页工具栏。

## 本机历史与离线磁盘

成功打开文件或打开所在位置后，记录完整路径、打开次数和最近打开时间，最多保留最近打开的 500 项。历史只存本机，不上传、不同步；设置中可单独清空，不删除文件，也不清除其他偏好。

已确认不存在的文件会从历史和当前名称缓存中移除。正常查询期间，曾由索引返回的历史项最多每五分钟通过 Everything 批量核验一次；失败或索引不可用时不贸然清空历史。不会为清理历史逐个检查文件、扫描休眠磁盘。直接粘贴但未被索引确认的路径不据此自动清理。

通过系统磁盘挂载信息判断已知离线盘，离线盘结果在排序和数量截断之前隐藏；设备状态变化会重新查询。磁盘暂时离线不等于文件被删除，不因此清空该盘历史。明确打开或粘贴某个路径时，才针对该目标检查存在性。

## 后台名称索引与刷新

主进程仅传递小型查询请求及最终结果。Everything HTTP 响应解析、中文名称列表、预处理的多音字拼音读音，以及逐项匹配评分都在独立 worker 线程内完成；每次查询不把约 4.6 万条名称搬回主进程，也不在主进程遍历它们。常用全拼、首字母及混合拼音匹配复用预处理结果。

名称索引每 **60 秒**尝试增量更新，使用上次成功时间之前两分钟的重叠区间，避免刷新边界漏项；每 **45 分钟**完整重建一次。普通刷新失败保留已成功建立的索引，完整响应被截断也不会覆盖旧索引。原字结果一直直接查询当前 Everything 索引。

- 默认增量仅用已索引的修改时间 `dm:`。
- 只有 ini 明确写有 `index_date_created=1` 时才同时使用创建时间 `dc:`。创建时间没有索引时，`dc:` 可能读取实体文件元数据，因此不会自动启用它，也不会修改 Everything 的全局设置。
- 普通新建或修改、且修改时间为当前时间的中文名文件，通常在下一次分钟刷新后可用拼音找到。
- **复制文件并保留旧修改时间**时，若创建时间未索引，新增中文名的拼音、插字和错字匹配可能要等下一次完整重建，最长约 45 分钟；按原字查询仍直接查当前 Everything 索引。删除、改名产生的旧缓存也由完整重建收敛，打开时发现确已不存在则提前移除。

## Everything 与本机查询口

本机已经安装带 voidtools 签名的 Everything 1.4.1.1009，程序位于 `C:\Program Files\Everything`，索引服务自动运行。不要重复安装或重新生成查询密码。

- 程序目录的 `Everything.ini` 使用 `app_data=1`；查询配置在 `%APPDATA%\Everything\Everything.ini`。
- 查询口绑定 `127.0.0.1`，使用随机端口及用户名、密码；禁止通过该查询口下载文件。ZTools 只连接本机地址，凭据从配置文件读取，不写入源码、日志或说明。
- Everything 查询进程未运行时，ZTools 在功能开启的启动预热或实际查询中尝试 `Everything.exe -startup`，不打开 Everything 窗口，不申请管理员权限。服务和查询进程不是同一件事：只有索引服务运行而查询进程未运行时，HTTP 查询仍需要启动后者。
- 连接失败会在文件专页显示简短提示。先确认 Everything 已安装、查询进程在运行、只限本机的查询口已启用；不要因此打开公网端口。
- 既有配置备份为相应 ini 的 `.bak-20261112`；插件自带的 Everything 副本已禁用其查询口及管理员启动，避免争用。安装维护脚本为 `scripts/local/install-everything-service.ps1`，卸载参数为 `-Uninstall`；不作为日常搜索操作使用。

查询语法基础参考 [Everything 官方搜索说明](https://www.voidtools.com/support/everything/searching/)，实际界面以本页列出的功能为准。

## 已知边界

- 搜索范围取决于 Everything 已索引的磁盘和目录；不承诺覆盖未索引位置或文件正文。
- 中文名模糊索引的分钟增量与 45 分钟完整刷新边界见上节。首次载入时先显示原字结果，模糊阶段完成后合并；不阻塞主线程等待逐项评分。
- 英文插字补查只在专页模糊模式启用，词长 4–16；英文错字补查只支持 5–10 字符词。主框不运行这部分较慢的补查。
- 专页显示前 200 条；候选查询每档最多取 400 条，中文名称缓存上限 30 万项。结果数用于提示继续缩小范围，不是完整磁盘导出；极宽泛查询不能保证列出所有模糊匹配。
- 文件图标按类型绘制，不读取每个文件的系统图标。正则语法由 JavaScript 先校验，再交给 Everything 执行；两者独有的语法不保证兼容。

## 验证与发布

`tests/helpers/fakeEverything.ts` 提供临时、带假凭据的本机索引服务。测试通过 `ZTOOLS_EVERYTHING_INI` 显式指定假配置；测试模式不读取真实 Everything 配置，也不查询真实硬盘索引。Electron 测试使用临时数据目录及隐藏窗口，打开文件、复制路径、右键菜单由模拟处理器接管。

已覆盖匹配排序、排除目录、拼音、错字、多词、正则、类型筛选、深度搜索、配置缺失、鉴权失败、取消旧请求，以及主框/专页交互、开关保存、过期响应、窗口高度和深浅色。截图需当次同意；普通验证不开截图，获准截图只含假数据并保存在不提交的 `test-results/playwright` 下。

本轮新增了实际 worker 线程的 46,000 项假索引性能测试，分别测量载入和查询阶段的主线程事件循环最大延迟，验收阈值均为 **20 ms 以下**。假 HTTP 服务也运行在另一个线程，避免把测试服务器序列化 46,000 条记录的工作误算成 ZTools 主线程开销。`verify.ps1` 将普通单元测试与该性能测试分开、串行运行；并行构建或其他高负荷任务仍可能影响测量，不能通过放宽阈值掩盖失败。

Win+V 焦点处理不新增全局钩子，也不读取剪贴板历史内容。本机实测 Win+V 由 `elegant-clipboard.exe` 接管，窗口类名为 `Tauri Window`、标题为 `ElegantClipboard`；三个身份字段均匹配时保留搜索窗口。它是独立的剪贴板程序，因此不额外要求搜索框收到 Win/V 按键（Windows 可能在无边框窗口收到之前消费这些按键）。其他 Tauri 窗口和普通失焦仍正常隐藏。Windows 原生 `TextInputHost.exe` 另按严格身份和本窗口 Win+V 状态识别，不把所有输入法或表情面板一概放行。

获准的完整 ZTools 源码隔离实例使用 TEMP 数据目录、fakeEverything 和真实 native addon；以禁用全局钩子的测试模式启动后，仅在该临时进程中放开 E2E 的自动失焦保留，确保实际执行生产焦点判断。已实测 Win+V 期间搜索窗保持可见、Esc 后主进程经过 preload/App 发出一次返回通知且输入框重新获得焦点，当时 Ctrl+V 将已知假路径放入搜索框并进入文件专页，翻译请求为 0（本轮改为粘贴保留文字、显式快捷键进入文件专页；焦点处理不变）。原生剪贴板监听在隔离测试中关闭，粘贴内容接口仅提供主动写入的已知假路径，不读取其他内容。

自动验证没有枚举或读取用户历史条目，未代替用户选取真实历史内容。2026-11-12 用户已自行确认本机 Win+V 使用正常，当前环境验收完成；Windows 原生剪贴板面板在其他环境仍未实测，不能据此表述为所有系统版本均已验收。

按 `LOCAL-WORKFLOW.md` 执行 `verify.ps1` → `stage.ps1 -SkipVerify` → 切换预览。实际切换前须从托盘正常退出 ZTools；保留关闭后的数据备份，并检查启动路径。Windows 自启项应指向新版本，核对时确认进程没有 MSIX 包身份，避免把虚拟化的注册表视图当成系统实际状态。推送远端仍需用户单独同意。
