# 原生监听退出清理

## 已确认的问题

2026-11-21 的 Windows 错误记录在 `ztools_native.node` 中报告
`0xc0000409`，模块相对偏移 `0x7db95`，fail-fast 参数为 7。
11 月 17 日和 11 月 21 日较早的退出转储也有相同签名，原生文件相同。
不能把 Windows 的通用“stack buffer overrun”标签直接当作根因。

有完整栈的旧转储显示 DLL 退出清理调用 `0xa9820`，该函数检查
`0xd72f8` 的线程 ID，非零时调用 abort，最终到达 `0x7db95`。
Ghidra 对同一模块的静态分析将该线程对应到鼠标监听的 start/stop。
主程序原来没有在退出时调用鼠标、剪贴板和窗口监听的 stop。

本机受控原生复现使用源码 Electron 的 Node 模式及同一个 addon。
调试器在测试子进程内拦截 `SetWindowsHookExW`，返回假句柄，**不安装
系统鼠标钩子**，不读取剪贴板、不创建可见窗口、不发送输入。

| 场景                               | 观察结果                         |
| ---------------------------------- | -------------------------------- |
| 启动鼠标监听，直接退出，不停止线程 | 同样的 `0xc0000409` 和 `0x7db95` |
| 启动后先 stop 再退出               | 正常退出，无上述异常             |
| 在 `process.on('exit')` 中 stop    | 正常退出，无上述异常             |

静态分析快照、转储分析与受控探针日志只留在忽略的 `.local-work`，不提交
用户转储或原生模块的反编译内容。发布包中的原生二进制没有被修改。

## 修复范围

- 获准退出时，在销毁窗口和关闭数据库之前，按顺序停止输入监听、快捷键、
  安装变化监听和后台服务。任一项失败不会跳过其余清理。
- 被拦截的退出不停止正常工作的监听。正常退出和直接 `process.exit()`
  都有幂等清理；退出期间迟到的初始化不再重启监听。
- 停止时先作废 JS 回调。旧订阅的迟到事件不能进入新一轮订阅。
- 启动失败会释放已获取的资源；释放失败保留“尚未确认释放”的所有权，
  明确释放成功之前不允许新建同类线程，避免覆盖仍可 join 的旧线程。
- 剪贴板和超级面板的在途任务在退出后不再排入新写库、翻译或显示操作。
- `logs/runtime-lifecycle.jsonl` 同步记录进程 ID、时间、退出阶段和退出码，
  每份最多约 256 KiB，保留一份轮转文件。没有输入正文、剪贴板内容或密钥。
- 鼠标复制粘贴与微信语音辅助程序未修改。

## 验证与边界

单元测试覆盖资源获取失败、释放失败、重入、迟到事件、异步初始化和
退出期间的剪贴板/面板任务。源码 Electron 测试使用临时 profile、假应用、
隐藏窗口，验证搜索响应和正常/直接退出的生命周期记录。

完整流程：`pwsh -File scripts/local/verify.ps1`，然后
`pwsh -File scripts/local/stage.ps1 -SkipVerify`。可在 verify 前设置
`ZTOOLS_STABILITY_TEST_MS=330000` 进行超过五分钟的隔离稳定性检查。
常规 E2E 不注册真实全局输入钩子；原生线程收尾证据来自上面的受控探针，
两者不能混为一谈。

**证据边界：**这次运行中退出的转储缺少完整线程栈。已证实并修复鼠标线程
遗漏 stop 导致的退出崩溃，尚不能据此断言当时最初触发退出的动作也已查明。
生命周期记录用于区分以后是否先发生退出请求、直接退出或没有 JS 退出回调
的终止。不通过定时重启掩盖异常，也不以一次短测试声称所有 native 问题已解决。

切换仍需从托盘正常退出并备份 profile，不强杀、不覆盖个人数据。

## 关闭启动终端导致运行中的进程退出

11 月 21 日 09:30，修复版主进程再次以相同原生异常结束。生命周期日志只有
started，未进入正常退出流程。转储没有完整栈，无法还原用户关闭的是哪个窗口。

本机针对实际使用的 Electron 测试了两种启动方式。测试为各组单独创建隐藏
控制台，等隔离的 Electron 报告就绪，检查控制台成员只包含测试进程后关闭
该控制台。原有 Start-Process -WindowStyle Hidden 方式下，Electron 是
控制台成员，随窗口关闭退出。使用 start-release-process.ps1 后，它不是
控制台成员，关闭窗口和启动它的 PowerShell 后仍然运行。

切换与回退脚本现在均使用这个启动器，仅在新进程的环境中设置
ELECTRON_NO_ATTACH_CONSOLE。正式实例启动后通过独立探针调用 AttachConsole
验证，返回 ERROR_INVALID_HANDLE (6) 表示目标没有控制台。这个检查须在
主进程已写入 started 且仍然存活时进行。
