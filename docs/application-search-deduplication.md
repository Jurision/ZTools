# 应用搜索去重

应用索引与主框结果共用 `src/shared/applicationIdentity.ts` 的安装身份规则，适用于已有和以后新安装的应用，不使用品牌排除名单。不删除磁盘快捷方式或用户的“本地启动”配置。

## 合并规则

- 同一可执行程序、相同启动参数的入口合并为一项，即使来自桌面、开始菜单、安装登记或本地启动，或者名称带有版本号、不同语言、用户自定义名称。
- 不同名称保留为搜索关键词；用任一名称搜索，显示的仍是同一应用。优先保留普通正式快捷方式及其图标，通过原 `.lnk` 启动。
- 工作目录、管理员权限、窗口大小等启动设置不再产生多条应用结果。同名、同一安装但参数不同的启动方式也收进一项；右键“其他启动方式”可选择原快捷方式，参数与权限仍由 Windows 处理。
- 普通程序的不同安装目录、并存版本、便携副本保持独立，不凭相同名称或图标跨安装合并。网页包与启动器的多个登记入口分别按下述元数据规则处理。
- 共用宿主的独立应用保留：例如两个不同网站的 PWA、同一游戏启动器里的不同游戏。它们具有不同名称和不同参数摘要；不能把共用 Chrome 或 Python 的所有项目当成一个应用。
- 安装补漏发现某个可执行文件已由快捷方式覆盖时，不再追加裸 EXE 入口。备用启动器只有在同目录存在可确认的主程序时才合并；识别产品名加 `Launcher`、`AppLauncher`、`Launch` 后缀，没有针对某个品牌的特例。
- Windows 路径统一大小写、斜杠和外层引号。无法确认目标或参数的特殊快捷方式保留原启动动作，不凭猜测隐藏独立应用。
- 应用缓存升级为 v14，首次启动自动重建；以后正常索引更新也执行同样规则。扫描失败保留旧缓存并允许重试，无须用户逐个排除或删除个人配置。

## 应用与启动入口分层（v14）

同一产品可能既有独立旧启动器，又有统一平台中的启动入口。可执行路径不同不能直接证明这是两款应用；启动器的版本号也不能当作游戏或目标应用的版本号。

- 以快捷方式的明确产品名称、EXE 发布者和启动器角色共同判断；名称只统一 Unicode、空白和大小写，保留版本、地区及版本类型后缀。不使用任何游戏或品牌白名单。
- 一个发布者下，同名产品只有一个独立产品启动器、一个带参数的统一平台入口时，归到同一结果。两个原始启动动作都保留在右键“其他启动方式”，默认采用平台中明确指定产品的入口。
- 同名存在多个独立启动器安装、多个平台目标或信息缺失时，不跨目录猜测合并。普通 EXE 的两个独立安装、不同发布者、不同游戏、不同地区/版本名称仍独立。
- 这是一条通用的入口归组规则，不代表已经读取并证明所有启动器背后的游戏文件完全相同。Windows 没有覆盖所有安装器的统一产品身份；遇到有歧义的安装保留入口并说明来源。
- 真正保留的同名选择增加小字说明：已知版本、浏览器渠道/配置、安装目录或系统激活目标；仍不能区分时附具体路径。普通无重名应用不增加说明。网格和纵向列表都显示，完整说明可悬停查看。
- 网页包同样支持右键“其他启动方式”，不再仅对本地 EXE 显示该菜单。

## 网页应用安装登记（v13）

同一网页应用可能同时由商店和浏览器登记为不同 Windows 包。包 ID 不同并不必然代表独立应用。扫描器异步读取原生枚举已返回的安装目录中的 AppxManifest.xml，不读取浏览器用户数据。

- 只有清单确认同一浏览器宿主（含 Stable/Dev 等渠道）、同一配置目录、同一网页应用 ID 和同一用户数据目录时才合并。保留商店入口为默认项，其余原始激活入口放入“其他启动方式”。
- 不同渠道、不同配置、不同网页应用、不同数据目录继续独立；不按 TikTok 或其他名称匹配，不卸载包。
- 缺少配置、启动参数冲突、未知开关、非 PWA、不可读或损坏清单均不猜测合并。XML 禁止 DTD 和外部实体，文件限制 512 KiB，隐藏读取进程限时 10 秒，返回身份摘要及用于来源说明的浏览器宿主和配置名称，不返回原始命令参数或用户数据目录。
- 本机已弃用的官方 ZTools 使用现有“隐藏应用路径”设置排除，与开发版的安装身份区分保持独立。该个人设置在退出、备份后写入，不在源码硬编码官方路径。

发布切换时，先备份并更新已有的受管理 ZTools 快捷方式，再启动新进程，避免第一次索引扫描读到上一版目标。快捷方式备份和目标映射保存在该次 profile 备份目录；不会更改指向其他位置的同名快捷方式。

## 来源治理（v12）

重复入口不只来自同一个 EXE 的多个快捷方式，也来自启动外壳、内部主程序、后台组件和包内 EXE。来源处理先于结果去重：

- 目录补漏不再因为“文件名以产品名开头”就把程序当成应用；只接受明确的产品入口或启动器。
- 安装登记提供独立安装范围，EXE 的产品、发布者与描述用于关联内部组件。登记中发布者的缩写不参与公司名称猜测，最终比较使用 EXE 的公司信息。
- 同一注册范围中的内部主程序已有正式快捷方式时，使用正式快捷方式，内部路径记为来源别名。这也适用于手动添加过内部 EXE 的本地启动项。
- 产品信息相同不能合并套件入口：多个正式快捷方式仍按各自目标与参数区分。内部组件只能关联唯一的正式入口，或描述明确对应的入口；因此 Word、Excel、配置工具以及不同 PWA 不会因为共用产品名而消失。
- 未创建快捷方式的应用继续由 App Paths、注册信息和有限目录扫描补漏。同一注册范围、同一组件的多个内部版本优先保留登记入口；不同安装根、注册来源与有歧义的并存版本分开保留。
- WindowsApps 包内 EXE 不作为裸程序再次收录，交由包应用扫描器提供正确的激活入口。
- 固定磁盘上已确认目标不存在的快捷方式不进入索引；不删除磁盘文件。无法确认目标、不可用外置盘或目标发生竞态变化时不擅自判定已卸载。
- 长名称/别名超过 32 字符仍可做文字匹配，限制的是模糊匹配开销，不是应用名长度。

## 元数据与边界

隐藏 PowerShell 进程通过标准输入接收快捷方式路径与原生解析的目标，以显式 UTF-8 解码，支持中文和空格路径。WScript 对 ID-list 快捷方式返回空目标时使用原生扫描结果。只读取文件，不执行程序；最多读取 1800 个快捷方式，元数据阶段约 5 秒、安装扫描另有 30 秒预算，总体超时 40 秒。

参数单独生成摘要，用来区分宿主中的独立应用；参数、工作目录、窗口方式和管理员标志另生成完整摘要，用来保留启动动作。普通启动记为 `default`，其他使用 SHA-256，不把原始参数返回、写入日志或保存进应用缓存。网络快捷方式、MSI advertised、旧虚拟机与 shim 等特殊行为保守处理。

快捷方式标志依据 Microsoft 的 [Shell Link flags](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-shllink/4d25bbad-09b7-4322-8c0a-521d268481bb) 与 [SHELL_LINK_DATA_FLAGS](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ne-shlobj_core-shell_link_data_flags)。

## 验证

- 100 个虚构产品、400 个不同来源和名称入口，正序、逆序、轮换来源顺序均归并为 100 个应用，别名和启动动作保留，重复归并结果不变。
- 覆盖不同安装、不同版本、独立宿主应用、同名启动配置、新应用刷新、目标变化、元数据缺失和安装补漏。
- 临时目录生成真实 Windows 快捷方式：中文与空格路径、不同参数、工作目录、最小化、管理员、空 WScript 目标；缺失 emoji 路径和损坏项安全跳过。只读测试夹具，不查询真实安装项。
- 隐藏 Electron 使用假应用与临时 profile，验证一个应用一个结果、别名仍能搜索、右键可启动指定变体、两个版本及独立宿主应用不误并、刷新后新应用自动去重。
- 自动化测试不读写真实 `.ztools`，不启动真实应用、不调用翻译服务、不操作鼠标或前台窗口。计算、显式翻译与文件折叠仍运行原有回归。
- 新增注册根解析、启动器/内部程序、后台组件、套件独立入口、商店包、重装后的失效快捷方式和 40 个未来虚构产品的嵌套版本目录测试。
- `application-discovery.spec.ts` 逐个输入名称与别名，检查最终可见结果。默认用假数据；可通过 `ZTOOLS_APP_REPLAY_PATH` 指定事先只读导出的本机应用元数据副本，在临时 profile 中回放（副本保存在忽略目录，不提交）。实测必须另外核对来源归属，不能把“生成的身份没有重复”当成“用户看不到重复”的证据。
- v14 增加 100 个虚构产品的新旧启动器组合、多安装歧义、不同发布者/地区、来源说明及刷新回归。隐藏窗口逐项检查同名保留结果的来源说明非空且各异，并核对右键菜单保留的全部启动路径；不实际启动应用。
